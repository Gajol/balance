Pattern catalog / PAT-007

When another system gives us a status or a category, we do not show its words. We map it to a short list we own and translate ourselves.

  • Status: Proposed, pending EA confirmation
  • Version 0.1 · 2026-10-24
  • Applies: Accessible by default, Bilingual parity, Secure by design
  • Main layer: Content and governance

Supports: A status reads the same, in both languages, wherever it appears.

  • Taxonomy and labels
  • Bilingual parity
  • Accessible experience and plain language

Found by the Solution Architect in the solution architecture (five availability values are translated by us). Not named by the EA. Offered as a candidate pattern, pending EA confirmation.

The rule

DO

Map every outside label to a fixed value set that we define and translate in both languages. Show the value as words. Leave anything unmapped blank and put it on a review list.

DON'T

Show the source's raw text, colour or code. It may be in one language, change without warning, or carry more than we agreed, such as a meeting title inside a status field.

When this comes up

  • Other systems give us labels: availability, status, category, reachability. We show some of them on our pages.
  • Their words are not ours. They may be English only, may change in a release, and may hold detail we agreed not to show.
  • The same status appears in several places. Different wording in each makes the site feel unreliable.

What pulls in different directions:

  • Fidelity to the source, against a clear and safe meaning for staff.
  • Few values that are easy to read, against many that are precise.

Design rules for this pattern

  • Use the set's words, never the source's.
  • Keep to seven values or fewer.
  • Show words, not only colour.
  • Leave unknown values blank.

How to test the experience

Check these with real staff, in English and in French, and with a screen reader. The pattern is met if the answer to each is yes.

  • Does every value show an English and a French name?
  • Does an unknown source label show nothing?
  • Is the status clear to a reader who cannot see colour?
  • Do two pages that show the same status use the same word?
  • Does the French reader find the meaning without help?
How it works
  1. Define the set. The Taxonomy / IA Steward writes three to seven values. Each has an identifier, an English name, a French name and a plain meaning.
  2. Make the meaning narrow. Say what each value does not mean (for example, no times, no reasons).
  3. Map outside labels. Match each source label to one value in a taxonomy crosswalk. Record the mapping, who made it and when.
  4. Blank on no match. An unknown label shows nothing and goes to the unmapped list. It is never guessed.
  5. Show words. The badge is text. An icon or colour may help, but never carries the meaning alone.
  6. Version the set. A change to a value or its translation is a reviewed change and ships in a release.
  7. Reuse it. One set serves every place that status appears: page badge, search filter, report.
  8. Measure per language. Count each value, and the unmapped labels, in English and in French.
Definition cards

Hover or focus any dotted term in this page to see the same definition.

Fixed value set

A short, closed list of allowed values for a label that comes from another system. Each value has an English and a French name set by us.

Why it matters hereStops raw text from another system appearing in one language only (Bilingual parity).

Taxonomy crosswalk

A maintained table that says which term in another system matches which term in our shared taxonomy, in both languages.

Why it matters hereOther systems use their own category names. The crosswalk translates them so their content lands under our terms, not beside them.

Shared taxonomy

One controlled list of terms (topics, divisions, content types) kept in both official languages and applied to content.

Why it matters hereThe same terms drive CMS pages, search facets and analytics reports. It is what lets us ask 'which HR pages are stale, and who owns them?'

Journey map

A picture of one person's path through a task, step by step, with what they do, think and feel at each step.

Why it matters hereIt shows where an experience breaks, so we fix the right step and can test it with real staff.

Wireframe

A plain sketch of a screen that shows what goes where. It leaves out final colours, wording and branding on purpose.

Why it matters herePeople can agree on layout, language switch and reading order before anything is built, and a vendor can show the same screen back.

Trade-offs

What we gain

  • The same words everywhere, in both languages.
  • Nothing the source adds can reach a page by accident.
  • Easy to test: a short, closed list.
  • A clean place to prove parity.

What it costs

  • Some source detail is lost on purpose.
  • The steward must keep the set and translations current.
  • Each new source label needs a mapping decision.
  • A set that grows past about seven values stops being easy to read.

When not to use it

  • The text is the content, such as a document title or a news headline. Use PAT-001 (index, don't copy).
  • Staff need the source's full detail. Link to the source and let it decide who sees it.
Checks every pattern must pass

Bilingual (official languages law)

Each value has an official English name and an official French name, reviewed together. A value cannot ship without both. No raw text from the source ever reaches a page, so no language can appear that we have not reviewed.

Accessible (WCAG 2.1 AA)

The value is shown as text. Icons carry alt text only where they add meaning. The names are short and plain, which also helps screen reader and low-vision users.

On-premises, no outside connection

The set and the mapping live in our own CMS configuration, shipped in the signed release. Nothing is looked up outside.

How to test a vendor proposal

Ask the vendor to show, not tell. The pattern is met if the answer to each is yes.

  • Can you show the full list of values, each with an English and a French name?
  • Does an unknown source label show nothing, and appear on a review list?
  • Does the page show the value as text, readable without colour?
  • Can you prove that raw source text never reaches a page?
  • Is the set and its mapping in version control and part of the signed release?
  • Is the same set used in the page badge, the search filter and the report?
