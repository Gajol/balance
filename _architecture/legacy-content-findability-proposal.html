We propose that the old content is findable from the first day of the new site, without copying every file. Each collection gets a description at launch, with a button that searches the old system using the visitor's own words where it allows that. We then index the files in order of need, with a link to the original. Owners decide what moves into the new site.

  • Status: Draft proposal for decision. Patterns cited are proposals.
  • Principles applied: accessible by default, bilingual parity, transparency
  • 2026-10-24

Decision requested

DECISIONApprove a describe-then-index approach in place of a bulk copy.

We ask the sponsor to approve the approach below. We also ask for a named owner for each collection in the old system, and a date for switching the old system off.

Nothing in this proposal stops a later move of content into the new site. It makes that move a choice by each owner, not a bulk load.

Background

The old system cannot connect to the new site. One proposal is to copy its files into the new site. Then the new site would be the one place to look.

There is a worry behind it. People find this content in the old system today. The new site will not find it until the copy is done. That gap could last months or years.

We share both aims: one place to look, and no gap. This proposal reaches both without copying every file.

Goal and measures of success

GOALNobody searches and finds nothing.

The goal is not that every old file lives in the new site. Copying is one way to reach the goal. It is the heaviest way.

  • At launch, every collection in the old system has a reference card that a search finds.
  • Searches that find nothing are counted in each language (bilingual parity), and the count goes down over time.
  • Click-outs from cards to the old system are counted in each language.
  • A coverage list is published. It shows what is searchable now, what is coming and what is not planned.
  • Every collection that is searchable has an owner and a review date.

Recommended approach

Four steps. Each one adds value on its own.

1. Describe, at launch

One reference card for each collection in the old system. It says what is there, who it is for, how to reach it and who owns it.

A search for the topic finds the card, not nothing. A card is a core CMS content type, so it is cheap to build.

PatternReference card (PAT-003)

2. Hand off the search, where the old system allows it

If the old system has its own search that takes words in its address, the card carries a button that opens it with the visitor's words already entered.

We change our terms to the old system's terms where we hold a crosswalk, and the page shows what was sent. The old system still applies each visitor's own access rights.

PatternHand off the query (PAT-014)

3. Index, as each collection is ready

Scan the files. Read their text in a sealed container. Put the text in the search index with a link to the original.

Staff find words inside the files. The old system stays the source of truth. We start with the collections people search for most.

PatternExtract documents in a safe pipeline (PAT-002), Index, don't copy (PAT-001)

4. Move, only if the owner chooses

For each collection the owner decides: keep, refresh or retire.

Only what is kept, and worth owning, moves into the new site as normal content in both languages.

PatternFlag, never remove (PAT-009)

A link back only works while the old system is running and staff can reach it. If it is switched off at launch, owners move what is worth keeping and the rest is archived (archive decision).

Why we do not recommend a bulk copy

CostWhat happens
Two ownersThe copy needs its own owner and review date. The old file still has one.
Stale fastThe old system keeps changing. The copy does not, unless someone runs an export job forever.
LanguageA file we publish must exist in English and French, and we must be able to prove it (bilingual parity). Old files often do not.
AccessibilityEvery copied PDF becomes our accessibility problem on day one (accessible by default). Many old files are untagged.
Access rulesThe old system may limit who can open a file. A copy loses that. We index only what every employee may see (search platform decision).
SafetyAn old file is untrusted input. We would run it through the safe pipeline anyway (Extract documents in a safe pipeline (PAT-002)).

A copy is the right choice in some cases:

  • The owner wants the content to live in the new site and will keep it current.
  • It can be published in both languages and passes the accessibility checks.
  • The old system is going away, so a link back would break.
  • Even then, we move one collection at a time, on the owner's decision. We do not bulk load.

How we manage the gap in the open

  • A coverage list. What is searchable now, what is coming, what is not planned. Each line has an owner of record and a review date.
  • A zero-result report. The analytics tool counts searches that find nothing, in each language (transparency). It shows which collection to index next, so effort follows real need.
  • A review date for the plan. It is not a promise of when every file is in. It is a promise to look again, in the open.

What we need from the sponsor

  1. A named owner for each collection. A position, not a person.
  2. Read-only access, or a scheduled export with title, owner, date and language.
  3. A list of collections, with rough size and how often staff need each one.
  4. A date for switching off the old system.
  5. A test of the old system's search address, with a few words in both languages.
  6. Agreement to publish the coverage list and the review date.

The three checks

  • Bilingual. Each card is written in English and French. Reachability uses a fixed value set with an official name in each language. The crosswalk holds each term in both languages. Search lag and zero-result searches are counted per language. No raw text from the old system is shown as a label.
  • Accessible. Cards are core pages built with standard design system components. Result links name the destination and the system. An untagged PDF found in the pipeline goes to the content health report as a gap.
  • On-premises. The crawl or export, the pipeline and the search engine all run inside the isolated network. A search handoff only goes to addresses on an approved list. Any "federated search" product sold as a hosted service is out. So is any tool that sends old files to an outside service.

Assumptions and open questions

  • We assume the site is for staff only. A public site changes the access and language rules.
  • We do not yet know how big the old content is or how much is still used. "Months or years" may be much shorter if only some collections matter.
  • We do not yet know if any old files have access limits.
  • We do not yet know when the old system is switched off.
  • We assume the old system's search accepts words in its address. We have not tested it.
  • For the Enterprise Architect: Index, don't copy (PAT-001) says never copy into the CMS. A read-only landing area for exports, feeding the pipeline, is not CMS content. Confirm this is allowed, or record it as an exception.

Terms used

Reference card

A short CMS page that stands for something staff need but we cannot crawl or link to. It says what it is, who it is for and how to reach it, and it has an owner and a review date.

Why it matters hereIt turns an invisible failure (a dead link) into owned, searchable, measurable content.

Search index

A copy of content organised for fast searching. It holds searchable text and metadata, and a link back to where the content lives.

Why it matters hereOne index per language, so neither language can hide the other.

Source of truth

The one system that owns a piece of information and is allowed to change it. Every other copy is a convenience that can go stale.

Why it matters hereEach page has one owner and one review date. A second copy has neither.

Owner of record

The named position accountable for a piece of content: for its accuracy, its review date and the decision to keep, refresh or retire it.

Why it matters hereA position, not a person, so a departure does not orphan the content.

Analytics tool

A self-hosted tool that counts visits and searches without tracking individuals. It can count searches that find nothing, in each language.

Why it matters hereIt shows which old collection people look for most, so we index that one next.

Fixed value set

A short, closed list of allowed values for a label that comes from another system. Each value has an English and a French name set by us.

Why it matters hereStops raw text from another system appearing in one language only.
