Pattern catalog / PAT-011

Every number we report is shown for English and French separately, side by side, so a gap cannot hide inside a total.

  • Status: Proposed, pending EA confirmation
  • Version 0.1 · 2026-10-24
  • Applies: P2, P4
  • Main layer: Content and governance

Supports: English and French are measured separately, so parity is proved with numbers.

  • Measurement and analytics
  • Bilingual parity
  • Accessibility assurance
  • Ownership and freshness

Found by the Solution Architect in the solution architecture (principle P2, per-language search lag and per-language analytics counts in the Solution Architecture). Not named by the EA. Offered as a candidate pattern, pending EA confirmation.

The rule

DO

Record the language of every page, event and record as a custom dimension or field. Report every measure per language, side by side, with the gap.

DON'T

Report one total or one average. A strong English number can hide a weak French one, and parity is then a claim, not proof.

When this comes up

  • The intranet must prove it is bilingual and unbiased on an ongoing basis (P2). Proof needs numbers, in both languages.
  • Totals are easy to produce and they hide the problem. Most dashboards default to a total.
  • Many measures exist: page counts, freshness, search lag, search success, accessibility results, traffic, flags.

What pulls in different directions:

  • A simple dashboard, against an honest one.
  • One shared definition, against each team's own count.

Picture it

The experience

An executive opens a dashboard and sees both languages, side by side, and any gap, without asking. The same dashboard serves Communications and IT with more detail.

Design rules for this pattern

  • Never show a total above the two languages.
  • Give the gap its own column.
  • Pair every chart with a table.
  • Name an owner role beside every flagged gap.

How to test the experience

Check these with real staff, in English and in French, and with a screen reader. The pattern is met if the answer to each is yes.

  • Does every report show English and French side by side with the gap?
  • Is language passed to analytics and search from the source?
  • Does a test gap over the limit raise a flag to a named role?
  • Does every chart come with a readable table?
  • Can a past month's report be reproduced?
How it works
  1. Set language at the source. Every page, file and record has a language. No guessing from the text later.
  2. Pass it on. Send language as a custom dimension to analytics and as a field to search, so every count can be split.
  3. Define each measure once. Name it, define it, and say how it is counted in each language. Use the same definition for both.
  4. Show both languages side by side. Every chart or table has an English column and a French column and the gap. No hidden totals.
  5. Set a limit. Communications sets the gap that triggers a flag, for example freshness or search lag.
  6. Flag gaps. A gap over the limit raises a flag (PAT-009) to the stewards.
  7. Protect people. Reports are aggregate. No report ranks or names an individual.
  8. Prove it on demand. The parity report can be produced for any date, so the claim can be checked later.

Trade-offs

What we gain

  • Parity is proved with numbers, not claimed.
  • A gap is seen early and has an owner.
  • One shared definition per measure.
  • Executives see the same truth as stewards.

What it costs

  • Dashboards are busier than a single total.
  • Every new measure needs a language split from day one.
  • Small samples in one language can look noisy.
  • Stewards must act on the flags.

When not to use it

  • A measure has no language, such as server uptime. Report it once and say why.
  • A sample is too small to mean anything. Show the counts and say so, not a percentage.
Checks every pattern must pass

Bilingual (official languages law)

This pattern is the proof. Both languages are measured with the same definitions, shown side by side, and neither is the default. Dashboards open on both languages, never on a total.

Accessible (WCAG 2.1 AA)

Charts have a table with the same numbers. Language names are written out, not abbreviated only. State (gap flagged) is in words as well as colour.

On-premises, no outside connection

Analytics and search are self-hosted (Self-hosted analytics for analytics, Search platform: self-hosted search engine). Reports are built in the CMS and analytics. Nothing is sent to an outside analytics service.

FLAG On-premises conflict

A hosted analytics or reporting service (for example Google Analytics) is not allowed on the isolated network. Use self-hosted analytics.
