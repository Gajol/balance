Observability and Security Monitoring for a Web Platform

Working paper. Send once, route many. Agree a log contract. Treat silence as a failure.

Contents

    Short answer

    Yes, IaC and CaC are part of this

    The pipeline does not carry the logs. It builds, tests and deploys the settings that do. IaC creates the hosts and containers and the path out of them. CaC sets the log format, the forwarder and the alert rules. Both live in Git, so a log cannot be switched off by accident and the link can be rebuilt on demand.

    Three ideas carry the design.

    1. Send once, route many. The platform writes standard logs. One local forwarder sends them to the enterprise collector. The SIEM and the NOC take what they need from there.
    2. Agree a contract. A small file in Git lists the required fields, ports, severity names and owners. The team and the enterprise both test against it.
    3. Treat silence as a failure. A heartbeat event every minute means a quiet link raises an alert. Without it, a broken link looks like a calm system.

    Terms in plain language

    Terms used in this paper
    TermWhat it means here
    LogA line of text a system writes when something happens, such as a sign-in or an error.
    EventA log line that matters to someone else, such as a failed sign-in, a role change or a deployment.
    TraceThe path of one request across CMS, Search and Analytics, with timing. It helps the team find slow steps. The SOC and NOC rarely need it. Start with logs and events. Add traces later by putting a request ID in every log line.
    SOC and SIEMThe Security Operations Centre and its tool. The SIEM collects security logs, looks for attacks and supports investigations.
    NOCThe Network Operations Centre. It watches that services are up, healthy and fast, and it runs incidents.
    ForwarderA small program on each host. It collects logs, adds tags, holds them on disk if the network fails and sends them to the enterprise collector.
    CollectorThe enterprise server that receives logs from every forwarder.
    Agent and shipperSmall programs on a host that send data elsewhere. A shipper only sends logs. An agent may also collect metrics and security data.
    BufferA holding area on disk for events that cannot be sent yet.
    HeartbeatA small event sent on a fixed beat. If it stops, something is wrong.
    DriftWhen what runs on a host no longer matches what Git says.
    Telemetry contractThe agreed list of fields, event names, port and owners, kept in Git.
    SyslogA long-standing standard for sending log messages. Almost every log tool understands it.
    TLSEncryption for data in transit. With certificates on both sides, each side also proves who it is.
    ELK and Elastic StackELK is Elasticsearch (store and search), Logstash (parse and route) and Kibana (screens). The Elastic Stack adds Beats.
    BeatsLight Elastic programs on hosts, each shipping one kind of data. Filebeat ships log files.
    LogstashA server that receives data, parses and enriches it and passes it on.
    OpenTelemetry (OTel)An open standard and toolset for logs, metrics and traces. Its Collector receives data and forwards it.
    IaCInfrastructure as code. Hosts, containers, networks and storage are described in files, not built by hand.
    CaCConfiguration as code. The settings inside those systems are described in files too: log format, forwarder, alert rules.

    Keep personal information out of logs

    The SOC needs a user ID and source address for investigations. It does not need passwords, tokens, form content or search terms. Privacy should confirm which fields are allowed. The pipeline checks sample logs for these items before release.

    How the signals travel

    Each source writes to the host. The local forwarder tags the events, keeps a copy on disk and sends them over an encrypted link to the enterprise collector. The collector feeds the SIEM and the NOC. The NOC also probes the platform's health endpoints. The pipeline puts the settings in place and registers the checks and alert rules.

    Where IaC and CaC fit

    IaC builds the place. CaC sets how it behaves. For observability, both matter, because a missing firewall rule and a wrong log format break the link in the same way: silently.

    What IaC, CaC and the pipeline each own for observability
    LayerWhat it defines for the SOC and NOC linkKept as
    IaCPodman Quadlet units now and Kubernetes YAML later, with the log driver set. Host settings: persistent journal, time sync, buffer folder, heartbeat timer. Network rule to the collector.Quadlet files, Kubernetes YAML, Ansible tasks
    CaCForwarder settings and certificate paths. CMS syslog settings. Analytics log settings. NOC alert rules. The list of health endpoints to register.Exported CMS config, config files, Ansible templates, alert rule files

    Enterprise sideCollector, SIEM parsing and detection rules, NOC probes and ticketing. These have their own IaC and CaC. The team agrees the contract and does not edit them.Owned by Security and Operations

    Why code beats hand-built

    • Repeatable. Test, staging and production send logs the same way, so the test proves something about production.
    • Reviewable. A change to what is logged goes through review, and Security can be one of the reviewers.
    • Traceable. Git shows who changed a log setting and when. That answers audit questions.
    • Recoverable. A lost host is rebuilt from Git with the link already in place.
    • Checkable. A daily job compares what runs with what Git says. A difference is drift, and it raises a ticket.

    What keeps the link resilient

    Resilience comes from two places. The pipeline stops a bad change from reaching production. Runtime controls keep logs flowing when the network or the collector has a bad hour.

    Pipeline controls

    Pipeline controls and the failure each one prevents
    StageControlFailure it prevents
    CodeLog settings, forwarder files and the contract are in Git. Changes to logging need a security reviewer.Someone turns off a log or renames a field by accident
    BuildSettings are built once, signed and listed in the release manifest.Test and production run different settings
    ValidateLint IaC and CaC. Check sample events against the contract. Scan samples for passwords and tokens. Send a test event and wait for it to arrive at the test collector.A format change that breaks SIEM parsing. A broken forwarder file. Secrets in logs.
    ReleaseThe SOC and NOC are told about changes to logging, ports or alert rules. Exceptions to a gate carry an expiry date.Surprise changes and permanent exceptions
    DeploySettings go with the app. The forwarder restarts. The heartbeat must return within five minutes or the deploy rolls back. A deploy marker is sent.A deploy that cuts the link while nobody is looking
    ObserveHeartbeat alert. Daily drift check against Git. Certificate expiry alert 30 days ahead.Slow decay: drift, expired certificates, a full buffer

    Runtime controls

    Runtime controls and what they do when the link is down
    ControlHow it worksWhen the collector or network is down
    Disk bufferThe forwarder queues events on disk before sending.Events wait on disk and are sent when the link returns. Size the buffer for at least a day of peak volume. Confirm the size with the SOC.
    Retry without blockingApps write to the local system log. The forwarder retries with a pause between tries.The website keeps running. A logging outage never takes the site down.
    Encrypted and authenticated linkTLS with certificates from the internal authority. Each side checks the other.Nobody can read or inject logs in transit. Renewal is automated, with an alert 30 days before expiry.
    HeartbeatA small event every minute carries the release number.After five minutes of silence the NOC is alerted. The SIEM also has a rule for a host that goes quiet.
    Second collectorThe forwarder lists two enterprise collectors, if the enterprise offers them.Events switch to the second one without anyone acting.
    One clockAll hosts use the same time source and write UTC time.Events from different hosts line up in an investigation.
    Protected settingsOnly the pipeline changes forwarder settings. A change sends a notice to the SOC.Logging cannot be quietly turned off by one person on one host.
    RollbackThe previous settings stay on the host.A bad logging change goes back with the release.
    Separate failure pathsThe NOC probes from outside the platform.If the platform dies and cannot report, the probe still sees it.
    Isolated-network fitThe forwarder reaches only the internal collector. No cloud service is used.Matches the data residency and network rules of the platform.

    Common tools

    A tool does one or more jobs. Pick by job, not by brand. The enterprise already runs the SIEM and the NOC, so the web team usually chooses only the first job below: the forwarder on its own hosts. The rest helps you talk with Security and Operations and shows what you may meet on their side.

    Short answer on ELK, Beats and Splunk

    ELK is Elasticsearch (store and search), Logstash (parse and route) and Kibana (screens). Add Beats, the light shippers on each host, and it is called the Elastic Stack. Splunk does the same jobs in one commercial product, with a strong search language and a ready-made SIEM add-on. Either can receive what the rsyslog example sends. Choose the one the enterprise already runs.

    Suggested starting point (to confirm)

    Use the collector and SIEM that Security and Operations already run. On the hosts, use the enterprise-approved forwarder. If there is none, start with rsyslog, as in the examples. When the platform moves to Kubernetes, look at Fluent Bit. If traces are added, put the OpenTelemetry Collector in front of whatever the enterprise stores them in. Do not run a second SIEM or log store for the team.

    IaC and CaC examples

    Illustration only. Not a deliverable.

    These show the shape of the code. Host names, ports, paths and metric names are placeholders. The DevOps team, Security and the NOC set the real values and tools.

    1. Repository layout

    IaC and CaC sit in separate folders. The contract and the tests sit beside them.

    platform-repo/
  iac/
    podman/            # Quadlet units, host settings, heartbeat timer
    kubernetes/        # the same services as YAML, used later
  cac/
    forwarder/         # forwarder settings and templates
    cms/config/     # exported CMS configuration
    analytics/            # log section of the Analytics settings
    ansible/roles/     # applies the files above to each host
  contract/
    telemetry-contract.yaml
  monitoring/
    alert-rules/       # heartbeat and health alerts for the NOC
    checks/            # health endpoints to register with the NOC
  tests/
    log-format/        # sample events and field checks
    drills/            # failure drill scripts
  pipeline/            # stages that extend the shared template

    2. IaC: run CMS under Quadlet with logs to the host journal

    The log driver sends container output to the host journal, where the forwarder picks it up. Search and CMS need no extra log shipping inside the container.

    # iac/podman/web-cms.kube
[Unit]
Description=CMS pod
After=network-online.target rsyslog.service

[Kube]
Yaml=/opt/web/deploy/rendered/cms.yaml
LogDriver=journald
PublishPort=8443:8443

[Service]
Restart=on-failure

[Install]
WantedBy=multi-user.target

    3. IaC: host settings for reliable logging

    # iac/podman/host-logging.yml  (Ansible tasks)
- name: Keep the journal on disk so a reboot loses nothing
  ansible.builtin.copy:
    dest: /etc/systemd/journald.conf.d/persist.conf
    content: |
      [Journal]
      Storage=persistent
      SystemMaxUse=2G

- name: Keep one time source for every host
  ansible.builtin.service: name=chronyd enabled=true state=started

- name: Create the forwarder buffer folder
  ansible.builtin.file:
    path: /var/spool/rsyslog
    state: directory
    owner: root
    group: root
    mode: "0750"

    5. CaC: CMS and Analytics log settings

    CMS's syslog module sends its events to the system log. The settings are exported with the rest of the CMS configuration. Source address and user ID are personal data, so confirm them with Privacy.

    6. CaC: the forwarder settings

    The forwarder reads the Analytics log file, adds tags, and sends events over TLS. The disk queue and endless retry are what protect the data during an outage.

    # cac/forwarder/50-siem.conf
global(
  DefaultNetstreamDriver="gtls"
  DefaultNetstreamDriverCAFile="/etc/pki/web/ca.pem"
  DefaultNetstreamDriverCertFile="/etc/pki/web/forwarder.pem"
  DefaultNetstreamDriverKeyFile="/etc/pki/web/forwarder.key"
)

module(load="imfile")
input(type="imfile" File="/opt/web/analytics/tmp/logs/analytics.log"
      Tag="analytics:" Severity="info" Facility="local1")

template(name="siem" type="string"
  string="<%PRI%>1 %TIMESTAMP:::date-rfc3339% %HOSTNAME% %APP-NAME% %PROCID% %MSGID% - %msg%\n")

if ($syslogfacility-text startswith "local") or
   ($syslogfacility-text == "authpriv") then {
  action(type="omfwd" target="collector.example.internal" port="6514"
    protocol="tcp" template="siem"
    StreamDriver="gtls" StreamDriverMode="1"
    StreamDriverAuthMode="x509/name"
    StreamDriverPermittedPeers="collector.example.internal"
    queue.type="LinkedList" queue.filename="fwd_siem"
    queue.spoolDirectory="/var/spool/rsyslog"
    queue.maxDiskSpace="2g" queue.saveOnShutdown="on"
    action.resumeRetryCount="-1" action.resumeInterval="10")
}

    7. CaC: apply the forwarder settings with Ansible

    The role keeps a backup of the old file, checks the full configuration and only then restarts the forwarder.

    # cac/ansible/roles/forwarder/tasks/main.yml
- name: Install the forwarder settings from Git
  ansible.builtin.template:
    src: 50-siem.conf.j2
    dest: /etc/rsyslog.d/50-siem.conf
    owner: root
    group: root
    mode: "0640"
    backup: true
  notify: restart rsyslog

- name: Check the whole configuration before any restart
  ansible.builtin.command: rsyslogd -N1
  changed_when: false

- name: Record the release for the drift check
  ansible.builtin.copy:
    content: "{{ release_id }}\n"
    dest: /etc/web/forwarder.version

    8. The telemetry contract

    This file is the agreement. The pipeline tests against it. The SOC and NOC review changes to it.

    # contract/telemetry-contract.yaml
version: 1
transport:
  collector: collector.example.internal
  port: 6514
  protocol: syslog over TLS
  clock: UTC from the enterprise time source
required_fields:
  - timestamp
  - host
  - app
  - severity
  - user_id
  - source_ip
  - request_id
  - release
severity_names: [info, minor, major, critical]   # use the enterprise names
heartbeat:
  interval_seconds: 60
  silence_alert_after_seconds: 300
  routed_to: NOC
security_events:
  - cms.login_success
  - cms.login_failure
  - cms.role_change
  - cms.admin_action
  - web.access
  - os.auth
deploy_marker:
  fields: [release, jira_ticket, approved_by, time]
owners:
  forwarder: web-team
  collector: enterprise-operations
  siem_rules: security-operations

    9. Pipeline: the gates that protect the link

    The first job blocks a build when the test event does not arrive. The second checks that the platform is talking again after a deploy.

    # pipeline/telemetry.yml  (generic CI syntax)
verify-telemetry:
  stage: validate
  script:
    - ansible-lint cac/ansible iac/podman
    - tests/log-format/check.sh contract/telemetry-contract.yaml tests/log-format/samples/
    - tests/send-test-event.sh --target test-collector --release "$RELEASE_ID"
    - tests/expect-arrival.sh --target test-collector --release "$RELEASE_ID" --timeout 120
  allow_failure: false

announce-deploy:
  stage: deploy
  script:
    - tools/send-deploy-marker.sh --release "$RELEASE_ID" --ticket "$JIRA_KEY"
    - tools/expect-heartbeat.sh --host "$TARGET_HOST" --release "$RELEASE_ID" --timeout 300

    10. CaC: the NOC alert for a silent platform

    # monitoring/alert-rules/heartbeat.yaml  (example format)
groups:
  - name: web-platform-telemetry
    rules:
      - alert: WebPlatformLogsSilent
        expr: time() - web_heartbeat_last_seen_timestamp_seconds > 300
        for: 2m
        labels:
          severity: major      # use the enterprise severity name
          route: noc
        annotations:
          summary: "No heartbeat from the web platform for 5 minutes"

    Proving it works

    A link that is never tested will fail when it is needed. These checks make the proof routine.

    Checks that show the SOC-SIEM and NOC link works
    CheckWhenPasses when
    Test eventEvery build, in the test environmentThe event reaches the test collector within two minutes with all required fields.
    Heartbeat after deployEvery deployThe heartbeat with the new release number is seen within five minutes.
    Detection testEach release that changes logging, and every quarterA burst of failed sign-ins in test raises a SIEM alert.
    Failure drillEvery quarter, in testWith the collector cut for an hour, the buffer fills and then empties after reconnection. No gap appears in the SIEM.
    Drift checkDailyRunning settings match Git. A difference opens a ticket.
    Certificate checkDailyNo forwarder certificate expires within 30 days.

    Questions for Security and the NOC

    1. What are the collector address, port and protocol? Is a second collector available?
    2. Which fields and event names must every log line carry? Who approves changes to that list?
    3. Which fields may include personal information, and which are forbidden?
    4. How long must logs be kept, and where? Does the local disk buffer count?
    5. Who writes the SIEM parsing and detection rules for CMS, Search and Analytics events?
    6. How does the NOC register health checks and alert rules? Can the pipeline do it through a request or an interface?
    7. Which severity names does the enterprise use, and which severities page a person?
    8. Can we send test events to a non-production collector and run a detection test there?
    9. Are there isolated-network rules that limit how the forwarder reaches the collector?

    Confirm before use

    Required fields, retention, severity levels and collector details differ between organizations. This paper is a starting point. It is a draft and has not been reviewed by the Enterprise Architect, Security or the NOC.
